Fixed closed-loop selection prompts
Each block below is a slot template — fill `[SUBJECT/ACTION]`, then swap exactly one channel per iteration. These are constructed templates; the field names and vocabularies inside them are corpus-derived [S3][S26][S1].

    "support_feel": "<tripod | steadicam | handheld | crane>",
    "duration": "<within provider limit>",

Loop A — Locked baseline (validates motion before adding camera).
`camera_motion: locked_off · framing: medium · angle: eye-level · support: tripod-stable · duration: 5s · subject_action: [SUBJECT performs ONE counted action]` Static camera is explicitly best for clear movement validation [S26]. Lock everything else, change only the action.
Loop B — Pressure curve (push vs pull).
Cycle: `locked_off → push_in → pull_back`, holding framing at medium. Push increases emotional pressure, pull reveals context/isolation [S26]. Score whether the meaning changed or only the jitter.
Loop C — Follow-through curve (pan/tilt/tracking).
Cycle: `pan` (horizontal), `tilt` (vertical), `tracking` (moves with subject). Each follows a distinct axis of subject motion [S26]. Keep one follow direction per clip.
Loop D — Reveal curve (orbit/rack/reveal).
Cycle: `rack_focus → reveal → orbit`. Rack focus and reveal are event-semantics tokens [S21]; orbit is flagged as continuity-risky [S26], so render it last.
Loop E — Impact/tempo curve.
Cycle: `whip_pan → impact_impulse → handheld_subtle`. Whip-pan is fast-transition but consistency-risky for AI [S26]; handheld adds realism/tension [S26]. Budget these seconds separately.
How the loop closes (the scoring gate)
After each render, score against a fixed rubric and change only the failing channel before re-rendering — never rewrite the whole prompt, which reintroduces stochastic geometry [S2][A2].

SCORE GATE (per clip):
  ✓ camera moved as named?         if NO → strengthen with reference/keyframe [S1]
  ✓ framing held within bounds?    if NO → reframe via zoom/position/crop [S10]
  ✓ angle consistent start→end?    if NO → pin endpoint frames [S4]
  ✓ subject NOT smeared by camera? if NO → split camera_motion from subject [S3]
  ✓ one move only?                 if NO → drop to Loop A, rebuild [S8]

Fallback order when a prompt phrase fails is fixed: camera reference video → shot-level native camera control → camera prompt phrases, because pure prose carries medium-high loss risk on the camera track [S1][S32].
Failure mode: cramming unzip/pickup/open/close into one clip collapses both subject and camera channels.

* Symptom: extra limbs, drift, camera doing nothing recognizable.
* Fix: keep each phase short, isolate single-shot physics tests from multishot storytelling, extend full-clip for continuity [S8][S4].
